# Sample RAG QA Test Runs

This document logs actual query responses generated by the RAG assistant during local testing against the ingested `RepoMind-AI` repository. It showcases the engine's ability to locate relevant code chunks and formulate accurate answers.

### Test Case 1: Embedding Models and Storage

**Question:**  
> Can you tell me about the usage of which embedding model here?

**Retrieved Chunks Context:**
- `backend/app/services/embeddings/local.py` (Local ONNX implementation using `Xenova/all-mpnet-base-v2`)
- `backend/app/services/embeddings/voyage.py` (`VoyageEmbeddingProvider` using `voyage-code-3`)
- `backend/app/db/models.py` (SQLAlchemy definition showing the side-by-side columns: `local_embedding`, `voyage_embedding`, and `openai_embedding`)

**Assistant Response:**
> In the current codebase you can spot three embedding‑model families:
> 
> | Provider | Model name (default) | Dimensionality | Where it’s stored |
| :--- | :--- | :--- | :--- |
| **Local (self‑hosted)** | `Xenova/all-mpnet-base-v2` / `nomic-embed-code` | 768 | `Chunk.local_embedding` |
| **Voyage (cloud)** | `voyage-code-3` | 1024 | `Chunk.voyage_embedding` (via `VoyageEmbeddingProvider`) |
| **OpenAI (cloud)** | – (uses the OpenAI API) | 1536 | `Chunk.openai_embedding` |
> 
> The evaluation results in `evaluation/data/retrieval_results.json` use the local model. The `VoyageEmbeddingProvider` class is prepared to send embeddings to the Voyage API, and the DB schema is set up to keep the three possible embeddings side by side.

### Test Case 2: RRF and Hybrid Performance

**Question:**  
> Is RRF implemented or not? Does hybrid evaluation, if implemented here, give better results than say vector search performed? Acc to updation just now.

**Retrieved Chunks Context:**
- `backend/tests/services/retrieval/test_service.py` (Hybrid search and RRF score validation tests)
- `docs/retrieval.md` (RRF algorithm documentation)
- `README.md` (Real baseline evaluation results table)

**Assistant Response:**
> **Is RRF implemented?**  
> Yes. The tests in `backend/tests/services/retrieval/test_service.py` exercise the hybrid search and explicitly verify RRF scoring, and the docs in `docs/retrieval.md` describe the RRF logic that the service uses.
> 
> **Does hybrid give better results than vector search?**  
> No. The baseline table in `README.md` shows the metrics for 270 benchmark queries:
> 
> | Search Strategy | Hit Rate@10 | MRR@10 |
| :--- | :--- | :--- |
| **pgvector (Dense)** | **55.93%** | **0.2350** |
| **Hybrid (RRF)** | 41.11% | 0.1354 |
> 
> The dense (vector) strategy outperforms hybrid in both hit‑rate and MRR (and also has much lower latency). Thus, the current evaluation indicates vector search is better than the hybrid RRF approach.
